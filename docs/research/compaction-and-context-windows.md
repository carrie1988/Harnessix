# Compaction与长会话窗口源码研究

- 更新日期：2026-09-08
- 范围：Harnessix Code 0.6.3
- 状态：研究完成；结论已由0.6.3自动Compaction运行时、活动窗口和语义Eval实现验证

## 1. 研究目标

0.6.2c限制单个工具结果并冻结模型视图，但不能限制历史持续增长。0.6.3需要在保留原事件事实、调用配对、效果审计和关键任务约束的前提下，为后续模型请求创建新的有界窗口。摘要生成本身必须受预算、取消、持久化和审计约束，不能成为普通模型循环之外的隐形请求。

## 3. 与Harnessix现有契约的对应

### 3.1 事实历史与模型窗口分离

压缩不能删除或改写Session原Event、完成Item、Action结果、Approval、Artifact与冻结工具视图。新的窗口应表达“版本化Summary + 保留后缀”，并记录被覆盖的原Item集合、来源摘要、前一窗口身份及选择策略。当前`CompactionContent`只是0.3的语义审计记录，不承担活动窗口选择；不能仅把它写进Session就宣称自动压缩已实现。

### 3.2 保留单元必须是闭合调用组

不能按单个Item数量随意切割。一个模型响应可能产生多个调用，其全部完成结果必须和调用一同保留或一同归入压缩来源。等待审批、等待Action、未完成Item与当前用户输入不能跨边界切开。已有Provider的消息配对校验继续生效，不绕过校验迁就错误窗口。

Codex的逐项删除和用户文本截断反映其内部消息语义，不能原样套用Harnessix的Call/Result/Approval/Effect分离模型。

### 3.3 Summary不是高优先级指令

压缩来源包含模型输出、文件正文和工具返回，均可能含有指令式文本。摘要应作为低信任派生历史，不得转成Runtime/User权限或工具执行授权。Runtime/User指令Fragment及当前用户消息继续独立保留。Action Runtime仍以原审批和效果事实执行，摘要里的“已批准”“已执行”不具有授权或对账效力。

关键约束不能只靠摘要器自称保留。测试应提供带来源的约束锚点、未完成目标、文件revision和效果状态预期，分别验证逐字保留项和语义保持项；缺失应使候选摘要拒绝发布。

### 3.4 压缩请求必须进入正式计费账本

Harnessix现有Model Attempt绑定普通模型步骤，Reducer只允许在CALLING_MODEL结算。直接从Context Planner调用Provider会绕过这些状态和用量事实；给摘要器复用同一个普通step又会混淆请求、预算与恢复。

后续契约必须明确请求用途、独立Attempt身份、预算预留、观测用量与结算状态，并复用现有Billing/Cost数据类型。只统计压缩后的Token节省、不统计摘要调用费用不满足生产契约。

### 3.5 故障与发布边界

候选生成和窗口发布必须分开。取消、超时、空摘要、结构错误、约束缺失或没有实质缩减时保留旧活动窗口；已经发生的摘要请求用量仍结算。只有来源指纹、当前窗口身份和目标预算校验均通过时，才以一个Session事务发布新窗口。

进程在摘要响应返回后、发布前退出，重启不能猜测该请求未计费并自动重发；必须留下Interrupted/不完整用量证据。提交后退出只恢复已提交窗口，不重新生成摘要或重新执行工具。

## 4. 实施顺序与结果

1. 已冻结窗口身份、闭合组选择、Summary来源和请求用途的ADR与领域契约。
2. 已实现显式受控压缩完整流程：规划、摘要请求、用量结算、候选校验、原子发布、窗口读取与诊断。
3. 已在相同流程接入轮前触发及受限的Provider context-overflow恢复；失败请求消耗普通步骤，禁止摘要重试和递归压缩。
4. 已增加多轮重复压缩、跨重启、真实v14→v15升级、双Adapter映射和六类任务语义保持Eval。Provider切换的综合策略由0.6.5完成。

这些是同一0.6.3切片的开发顺序，不按辅助函数或契约文件数量宣告生产完成。总量、失败阈值和成本上限须进入正式配置与测试，而不是照搬上游默认值。

## 5. 已决策问题与保留边界

- Compaction Attempt使用独立账本，与普通Attempt共享Turn总Token和截止时间；
- 活动窗口通过Compaction ID、稳定Summary投影、冻结Tool Result决定和原始历史高水位绑定；
- 剩余预算不足、无闭合前缀、摘要无缩减和连续溢出均明确停止，不自动重试；
- 被窗口覆盖且已过期Artifact的长期保留策略仍仅作为审计事实，不承诺可回读；
- Fork继承Summary来源时的Thread归属和效果权限隔离由0.6.4定义。

自动压缩已按ADR、契约和失败测试接入；历史8 MiB保护上限仍然有效，不描述为无限长会话。

## 6. Harnessix端口约束复核

对照Harnessix自身`models/_anthropic_mapping.py::build_request`，现有端口明确要求消息以user开始和结束，不支持assistant prefill。因此不能把上游的“Summary + recent”直接映射为以助手摘要开头的历史，也不能通过修改旧Adapter来放松协议。首窗口规划固定首条原用户消息，将低信任助手摘要插在其后，并保留当前用户及工具配对。真实SQLite Session和双Adapter映射已纳入对应测试。

`agent/models.py::Item`没有model_step；规划器仅在用户边界或完整结果组结束处切分，连续助手文本保守合并。固定一个结果锚点会保留整个助手/调用/结果组，避免仅按Item计数留下孤立结果。固定集与连续后缀的正式分区、预算和失败语义见[窗口规划详细设计](../compaction-window-planning.md)。
