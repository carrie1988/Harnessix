# ADR 0106：1.0首发范围与风险分层发布门禁

- 状态：已接受；具体能力和工作包仍须实施验收
- 日期：2026-09-28

## 背景

0.9剩余工作同时包含本地编码产品发行和远端生态、全部模型认证、自动更新、通用数据维护等能力。
用全部候选方向作为商用前置条件会持续扩大验证组合，而不能保证真实编码任务先获得可靠结果。
现有20 Trial严格结果0/20以及许可/Windows失败仍必须如实保留。

## 决策

1. 保留本地优先、单Agent、三平台原生核心编码闭环和现有CLI/TUI、stdio、Python SDK。
2. 将剩余首发工作合并为R1安全/恢复、R2权利/发行输入、R3真实质量/有限模型认证、
   R4三平台发行、R5小批Beta、R6正式封板。
3. 至少一份Provider/模型/地域/模式配置通过真实认证；两类Adapter和离线契约保留，
   更多模型及完整价格矩阵不阻断1.0。未认证组合不得被描述为正式模型支持。
4. 远端MCP/OAuth、Agent公网Push、自动更新、多安装器、跨机Key迁移、旧历史补签、
   通用GC/维护平台和扩大评测生态后置；已退役独立Action服务不恢复。
5. 延期的高风险能力必须不装配或正式拒绝，不能仅从界面隐藏或标注实验性后继续暴露已知缺陷。
6. 现有机制及证据先做适用性核对；不重复实现控制、不逐小提交等待全矩阵。
   固定发布候选和正式版本仍必须通过完整必要门禁。
7. 保留重大变更完整设计、来源和测试映射；局部修复同步原资料，候选交付集中证据包。

本决策细化而不废弃ADR 0062/0063的产品定位和Windows原生要求。
延期不计作完成，也不改变已冻结失败和原始证据。

## 选项与取舍

- 拒绝“降低安全、取消、恢复、许可证或真实任务验收要求”：会失去正式产品的基本保障。
- 拒绝“保留所有功能开关但只删除路线图条目”：没有减少可达攻击面。
- 拒绝“只有Smoke通过即可商用”：不能解决现有真实编码结果0/20。
- 选择统一Wheel和手动停机升级，减少渠道复杂度；仍验证安装、匹配Key备份、迁移和失败恢复。
- 选择有限OS/架构及模型认证，不扩大支持声明；Windows原生写入和进程要求不被取消。

## 后果与验收

首发不具备远端扩展平台和自动更新等便利性，但保留真实本地软件工程产品能力。
现有阶段编号继续追溯，实际执行队列及退出条件以
[范围收敛总体与详细计划](../changes/m09-to-v1-release-scope-convergence.md)和[路线图](../roadmap.md)为准。
实现限制、正反例、发行物和Beta证据未到位时，不得把本决策当作1.0完成证明。
