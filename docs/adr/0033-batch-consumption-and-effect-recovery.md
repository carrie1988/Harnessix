# ADR 0033：整组一次性消费、部分效果与只核对恢复

- 日期：2026-09-04
- 基线：`f0adddc`，CI `33860637921` 四项通过
- 状态：c2b 已实现并完成本地/独立 wheel 验收，跨平台结果以对应提交 CI 为准；不接入 Kernel 批量工具

## 1. 契约与事实来源

保留 c2a 的完整组计划与唯一审批决定，新建独立 `BatchRunRecord/v1`：绑定 workspace_id、batch_id、approval_fingerprint；phase 为 started/finished，stop_reason 为 completed/cancelled/timeout/failed/interrupted 或尚未终止时的 None。每组最多两个事件：持久开始、持久终止。开始事件存在即消费批准，不删除、不重置，不因观察到前镜像而再次消费。

`BatchExecutionResult/v1` 组合该记录、有序成员身份/单文件状态及聚合效果。成员状态来自已校验的既有单文件事件，不在组事件里重复缓存整份效果快照。这样恢复核对更新成员事实后，不需要反复追加组终态或将崩溃窗口中的旧快照冒充最新已知事实。

效果严格区分 not_applied/applied/partial/unknown。pending、approved、failed、observed_before 是已知未应用；applied、observed_after 是已归因应用；started、uncertain、diverged、missing、unavailable 是未知。任何未知优先，不能按剩余成员推测“全部失败”。成员列表明确显示未知者和未开始者，不将它们写成执行失败。报告是历史归因，不保证当前磁盘仍等于已应用镜像；计划 Diff 仍不是实际效果 Diff。

## 2. 执行与顺序

`ManagedPatchBatches.execute(batch_id, fingerprint, operation)` 只接受完整批准且没有开始记录的组。先持久开始，再在同一操作预算下复核整组所有前镜像及写准入条件；陈旧组不启动文件写入，但批准已消费，不允许原批准重试。对每个成员再次检查组事实和前缀顺序，仅在轮到该成员时镜像组批准，随后复用原单文件执行器。其持久 started/临时 inode 证据先于替换，最终写前仍复核。

只允许“已归因成功前缀 + 至多一个非成功已调度成员 + pending 后缀”。第一处失败、未知、取消或超时终止调度。成功成员不回滚，之后的成员保持 pending。最后一次替换后取消也要保留 all-applied 的真实效果，但终止原因可以是 cancelled/timeout，不能以文件效果覆盖宿主终止事实。

原单文件 execute/reconcile 拆出内部共用实现，公开写入口仍拒绝组成员；组实现不借旧公开接口绕过授权，不新建替换器。仅持有副本锁的内部编排可进入共享实现，私有 Python 方法不构成抵御同 UID 恶意宿主的沙箱。

## 3. 查询与恢复

get_execution 只读已持久事实；未消费返回 None，不自动创建开始记录。组仍 started 时，可以已经存在全部或部分文件效果，但不能冒充已正常完成。

reconcile 只加载已有组及成员，复用单文件观察；不 prepare/save/reply/execute，不改变目标文件。仍 started 的组核对后以 interrupted 终止，即使全部文件已应用也不改称正常完成。已 finished 的组保留原终止原因，未知成员可进一步观察，效果随最新已知证据更新。观察仍不足则保留 unknown；不存在自动续跑或自动回滚。

执行中的预期异常尝试持久终止并返回效果；存储不可用时可无法发布结果，原开始记录仍使批准不可重用。异常退出交由宿主处理，但恢复只能核对。原操作取消后只为已发起效果的记账使用新的有界内部读预算，绝不据此调度下一文件。恢复自身的取消/超时可在部分观察已记账时返回异常，后续仍只核对。

## 4. 账本 v3 与配额

新增 batch_run_events，保持 v1→v2 的 DDL 与两份组计划/审批 Schema 不变。v2→v3 在独占副本锁、完整旧计划/组审批校验之后事务创建新表并推进版本；旧 v2 wheel 拒绝 v3。v1 先按原迁移升 v2，再独立升 v3，中断可停留在完整中间版本。升级不执行已批准组，也不改写旧事件/镜像或目标文件。

每个运行事件最大1 KiB、每组最多2事件，现有64计划上限使运行事件逻辑载荷总量最多128 KiB；不承诺SQLite物理磁盘预留。数据加载必须交叉检查完整组绑定、已批准决定、运行事件顺序、所有成员顺序/决定和既有单文件事件；未知版本、错绑、越序或开始记录丢失后出现成员执行事实均拒绝。

## 5. 验收门禁

真实三文件正常执行、所有成员位置的失败/取消/超时、替换前后 fsync/结果存储异常、组意图/成员批准/每文件替换与结果/组终止发布的真实退出矩阵；恢复不改变源目录、目标 inode/mtime/ctime，不调用任何写入口；未知归因不能只靠后镜像字节。覆盖前缀状态机损坏、旧接口禁止拆分、重复执行拒绝、审批/工作区错绑和旧 v2 wheel 升级。最后执行全量/异步调试、基础 wheel、中文文档与跨平台 CI，c3 的模型工具/Artifact 保持待开发。

实际验收及复现入口见 [测试第25节](../testing-and-evals.md#25-053c2b-顺序执行与部分效果恢复验收2026-09-04)；默认模型工具仍为原单文件版本，不将宿主组闭环称作模型批量闭环。
