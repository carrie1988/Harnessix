# ADR 0036：真实整组差异报告与归档准入

- 日期：2026-09-04
- 基线：`1c02c22`，CI `33885067939` 四项成功；开工 fetch 已确认远程可达
- 状态：c3c1 已实现，验收证据见测试第28节；c3c2 的 Session 事务发布按 ADR0037 实现；下文保留 c3c1 当时的设计边界

## 1. 源码求证与分片

已核对 Kernel、整组桥接/账本、精确编辑 Diff、Artifact 契约、SQLite 发布/读取/清理和 migration6。现有 `publish` 只接受成功只读调用；`_reference` 只核对成功 ToolResult 的 `output.artifact`；`agent_artifacts.call_id` 唯一，不能同时保存一个调用的计划与效果。Kernel 的整组公开输出也严格校验为原结构，不能任意套 `preview/artifact`。直接放宽这些条件会破坏权限及结果语义。

因此分成两个有实际验收的切片，不把准备报告称为已发布 Artifact：

1. **c3c1（本片）**：真实调用/组账本绑定的计划与历史效果报告；版本化 JSONL、逐记录/整体预算、完整成员说明、可重开的只读异步生成；不改 Session 或模型工具。
2. **c3c2（后续）**：独立计划/效果引用及会话事实的事务发布；按实际结构完成新 Agent/reader/数据库迁移、读取/配额/过期、双 SDK 与存储/真退出验收。只有此片通过才完成 c3c。

## 2. 报告而非执行许可

计划视图展示完整原计划中的有界编辑，来源后来改变仍可展示，但不表示当前可应用。效果视图必须有原完整调用计划、Session 宿主传入的批准和**精确匹配当前账本的已结算运行快照**；无运行的已镜像决定可展示未开始，started 运行拒绝展示结算效果。查询不执行 reconcile，不补写观察事件，不主动改变已知状态。

只为 applied/observed_after 成员输出历史效果编辑。unknown 与未执行成员始终有独立成员记录，但不带编辑正文；后缀不能冒充已修改。运行原因与效果独立：全部已归因但 cancelled/interrupted 不改成正常完成。相同后镜像字节不构成新的归因证据，报告不读取当前目标内容，更不保证目标此后未变。

宿主准备载荷保留完整计划/批准/运行，默认 repr 不输出私有身份或文本；公共正文不含成员 ID、批准人、调用审批摘要、私有根目录。工作区相对路径、镜像摘要及选中的代码预览仍属于正文，不宣称通用脱敏。该载荷不是 capability 或 Session 活跃性凭证，未来发布器必须重新绑定实际 Session 事实。

## 3. JSONL 与预算

记录顺序为 summary → 全部有序 file → 有序 edit 前缀。每条记录（包含末尾换行）不超过24 KiB，整体不超过1 MiB；默认64 KiB，预览默认1024字节、最大4096字节，完整长度和 SHA 不因截断改变。复用原 UTF-8 字节坐标/精确区间算法，不重新匹配通用 Diff。

必须先容纳 summary 与**全部成员说明**；预算不足明确失败，不用隐藏 unknown/未执行成员腾空间。只有编辑记录可按前缀截断，不跳过大的早编辑去展示晚编辑。`complete` 仅表示所选视图的全部可展示编辑与文本均已返回，不表示组执行成功、效果全部已知或取得批准。最终按实际 JSON UTF-8 和换行长度验收；JSONL 可由现有记录校验器读取，但本片不调用只读发布器伪造归档。

## 4. 生命周期与兼容

在原 ManagedPatchBatchBridge 上增加独立宿主报告方法，复用 `_run` 的串行、5秒操作预算和取消排空；不改变 `definition()` 或原写端口接口。宿主仍须传播原 Turn 生命周期。借用同一副本锁加载/校验历史镜像及运行，关闭等待线程排空，报告不调用 prepare/save/reply/execute/reconcile 或读取目标文件。

Agent v7、Session migration8、副本v3、Provider v3、现有 Schema/工具定义和依赖不改。没有实际新持久事实，不提前建立未来空表或提升 reader 标记。

## 5. c3c2 设计门禁

计划引用必须与真实审批请求同事务；效果引用必须与真实 ToolResult/私有效果同事务，失败/部分/未知不伪造 succeeded。同一调用允许两种用途，但不能复用或覆盖彼此；旧只读归档语义和唯一性须保持。需为独立引用选定最小事件结构，验证 Reader 升级及所有旧事件原字节，不借修改工具定义悄悄使既有等待审批失效。

发布器必须验证当前 Thread/Turn/Call、完整审批与报告载荷、真实效果摘要；分页/过期和引用也验证该归属。不能只验证正文自洽或信任宿主传来的任意 bytes；不能跨 Thread 或把模型提供的计划当批准。报告完整性与是否存在正文/是否过期分开。

归档失败不得妨碍真实写效果结算；预算不足、配额耗尽、取消、重开、事务回滚及提交后丢确认均需验证。恢复不重新执行写工具，不能把记录已发生效果的恢复预算变成新写许可。不得通过伪造 ToolResult 给计划展示占位，或将写结果包装成旧只读发布请求。
