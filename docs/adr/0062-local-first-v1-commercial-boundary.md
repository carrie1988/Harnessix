# ADR 0062：Harnessix Code 1.0本地优先商用边界

- 状态：已接受
- 日期：2026-09-08

## 背景

Harnessix Code已经完成0.1至0.6的Action Plane、Agent Runtime、Model Runtime基础、Coding Tool Runtime、Context与持久会话能力。后续阶段需要从运行内核建设转向安全执行、完整工程交付、客户端协议、扩展机制、质量工程和正式发布。

既有文档同时使用“本地优先”和“支撑大量真实C端用户”描述产品目标，但没有明确用户规模究竟表示大量独立本地实例，还是集中式多租户SaaS。若把远程Sandbox、多租户、分布式调度、云端密钥托管和计费控制面全部纳入1.0，项目会在单Agent可靠性尚未完成产品化前扩张为云平台建设；若只保留功能演示，又不满足正式商用版本要求。

## 决策

1. Harnessix Code 1.0定位为**面向大量独立终端用户安装和长期使用的、本地优先的生产级Coding Agent商业版本**。
2. “大量用户”表示同一版本能够在大量相互独立的macOS、Linux和Windows终端实例中可靠安装、升级、运行、诊断和恢复，不表示1.0提供集中式多租户云控制面；Windows平台语义由[ADR 0063](0063-windows-v1-platform-support.md)约束。
3. 1.0必须形成真实仓库中的“理解—规划—修改—执行—验证—审查—交付”闭环，包含通用多文件事务性交付、受控命令与进程、Git检查点和回滚、持久会话、安全执行、CLI/TUI、Headless App Server、MCP/Skills及可复现评测。
4. 远程Sandbox、云任务、多租户身份与配额、分布式Session/Worker、团队集中策略、云端Secret托管和计费控制面进入1.x候选范围；只有真实用户证据证明必要时才立项。
5. 0.7调整为“可信执行与工程交付”，0.8调整为“产品运行时与扩展”，0.9调整为“Release Candidate与质量工程”，1.0负责冻结契约并完成正式发布。
6. 评测不是0.9才开始的独立功能。0.7及其后的每个纵向切片都必须包含确定性回归、按风险选择的故障注入、真实仓库场景和必要的受控真实Provider验证；0.9负责汇总为可公开比较的发布基线。
7. 参考项目只作为架构、行为和失败语义的研究证据。研究必须记录固定提交或产品版本、来源和Harnessix独立决策；任何代码复用必须满足许可证和归属要求。

## 结果

### 正向结果

- 1.0的规模、安全和部署边界可验证，不再把本地产品与多租户SaaS混为一谈；
- 后续路线覆盖完整Coding Agent产品，而不是停留在Runtime库或受控工具演示；
- 云平台能力不会提前稀释单Agent可靠性、安全执行和真实工程闭环；
- 本地实例的协议、持久化和执行端口仍为1.x远程运行保留演进空间。

### 成本与风险

- 0.7需要同时补齐Sandbox、通用进程和事务性交付，必须进一步拆分纵向切片；
- 大量独立安装会提高兼容、升级、诊断、数据生命周期和发布物验证成本；
- 本地Host模式不能宣称强隔离，Container后端不可用时必须失败关闭或准确展示安全级别；
- 1.0不提供多租户云服务，不能使用云端并发规模作为发布声明。

## 被否决方案

### 将集中式SaaS纳入1.0

该方案需要身份租户、远程执行池、调度、配额、KMS、对象存储、计费、滥用治理、容灾和服务SLO，超出当前单Agent产品主线，显著推迟可发布版本。

### 只发布Runtime库或功能Demo

该方案缺少终端产品、通用工程交付、安全边界、安装升级和真实用户验证，不满足生产级Coding Agent目标。

### 保持0.7至1.0的宽泛功能清单

原有里程碑方向正确，但缺少纵向切片、完整交付链路和连续评测责任，容易在阶段末集中暴露安全与产品化缺口。
