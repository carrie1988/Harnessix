# ADR 0037：整组差异报告的事务发布

- 日期：2026-09-04
- 基线：`33e690e`，开工 fetch 确认与远程一致
- 状态：已实现并通过本地全量与真实旧 wheel 升级验收；证据见测试第29节，远端以本片提交 CI 为准

## 决策

新增显式启用的 `SQLiteBatchDiffPublisher`，绑定原整组桥接和同一 Session 的 Artifact 存储。Kernel 只把原事件批次交给它；调用者不能传入任意正文或自行拼装的报告作为发布凭证。发布器根据真实未结算调用、完整审批和效果，调用原桥接生成报告，再在同一 SQLite 事务插入正文及带引用的原事件。普通只读发布接口不放宽。

计划引用放在整组审批的 `diff_artifact`，效果引用放在 ToolResult 的独立同名字段；公开组输出保持原结构，私有执行证据保持原样，不把失败、部分或未知效果改为成功。批准时引用不可改，完整计划仍是审批指纹的唯一来源。空引用不序列化，旧事件原字节保持不变。新引用需要 Agent v8；新增 migration9，将 Artifact 唯一约束从调用改为调用与用途，旧行用途为 `tool_result`，新用途为 `batch_plan` / `batch_effect`，禁止互相覆盖。

读取及清理按用途校验真实 Session 引用；复用原有 Thread/工作区隔离、分页、TTL、活跃会话保护和配额。模型历史仅额外暴露效果引用，不发送审批人、私有计划或执行身份。报告完整度不是执行成功标志。

## 失败与恢复

报告准备、正文配额或引用预算不足时可以省略报告，不省略真实审批/执行事实。报告事务故障必须回滚，随后以原事件结算；提交后丢失确认必须按原事件身份读取已提交事实，不能重生成引用或重写文件。Session 自身不可用时仍明确失败，不能声称已持久化。取消排空沿用桥接的有界生命周期；恢复生成只读历史报告，不获得执行许可、不刷新原 Turn 写预算。无完整效果证据不生成效果报告。

## 验收

- 同一真实调用同时保有计划与效果引用；二者各与 Session 事实原子提交。
- 拒绝、部分、未知、正常执行及恢复均保持原结果语义；伪造载荷、跨归属、旧事件夹带引用拒绝。
- 两种用途分页/配额/TTL/活跃保护，以及旧只读 Artifact 回归。
- 插入、提交前、提交后真实退出，重开不重写；历史 Schema 原字节和实际旧 wheel 升级。
- 双 SDK 的离线 wire 校验、全量测试、中文文档同步。
