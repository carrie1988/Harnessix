# ADR 0034：整组调用桥接与 Kernel 接入边界

- 日期：2026-09-04
- 基线：`6a7cc65`，CI `33867929295` 四项通过
- 状态：c3a 已实现并通过本地/独立 wheel 验收，跨平台以本片 CI 为准；c3b/c3c 尚未实现，不将桥接完成称为模型批量闭环

## 1. 源码求证与分片

已检查 `agent/runtime.py`、`agent/approvals.py`、`agent/patching.py`、`agent/execution.py`、`agent/ports.py`、`patches/agent_bridge.py`、`managed_batches.py`、`batch_execution.py` 与 `artifacts/sqlite.py`。当前 Kernel v6 只接受单文件 `apply_patch` 专用端口；通用写工具即使注册也不会向模型广告或执行。现有 Artifact 发布器强制只读成功调用，并要求同一 Session 与 Scoped 入口；不能通过伪造只读调用把写效果归档。

为保持旧单文件路径不变，c3 分为三片，必须全部验收才能完成 c3：

| 切片 | 内容 | 当前范围 |
| --- | --- | --- |
| c3a | 独立整组调用契约、宿主异步桥接、完整调用/计划绑定、取消排空与只核对恢复 | 本片实现 |
| c3b | Kernel 专用整组端口、持久组审批/消费/结果、Session reader 升级、两个 SDK 离线闭环和组合崩溃 | 待实现 |
| c3c | 基于实际调用的计划/历史效果 Diff Artifact、分页/预算/过期、事务发布及恢复 | 待实现 |

c3a 不改变 Agent v6、Provider v3、Session migration7、副本账本 v3、既有 Schema 或单文件工具定义。它不读取 Session，因此受信作用域只能证明调用字段一致，不能证明当前调用活跃、宿主已持久消费等待边界或 Turn 尚未过期。宿主仍承担这些前置条件。

## 2. c3a 契约与准入

独立 `ManagedPatchBatchCallPlan/v1` 包含 Thread/Turn/Call、完整调用指纹及完整 `ManagedPatchBatchPlan`。后端稳定请求使用独立策略标签和调用归属摘要；外层审批指纹覆盖整个计划，不能使用旧单文件、只读调用或后端组审批的指纹代替。计划最多为既有64 KiB组计划加1 KiB绑定开销。模型输入仍复用严格 `PatchBatchProposal`，不能夹带批准人、工作区或计划 ID。

`ManagedPatchBatchBridge(copy)` 只暴露单一 `definition()`，工具名为 `apply_patch_batch`，版本摘要绑定副本身份、工作区策略、输入/输出/完整计划 Schema 和操作时限。不是通用 ToolRuntime，也不自动注册到 Kernel。

- prepare：稳定请求查找；缺失才整组准备/预留；已有计划必须完全匹配且无决定/无运行；复核全部来源。
- review：只核对完整调用计划；未决定且未运行；拒绝审批可不复核来源，不记录批准。
- execute：宿主先持久批准并消费等待边界；桥接核对全部绑定和唯一决定，镜像组决定后调用已有一次性组执行器；没有开始记录才允许进入。拒绝只保存组决定，不制造文件执行结果。整组前镜像预检由后端在持久消费后完成，陈旧组也消费旧许可，禁止重试。
- recover：只查原稳定请求及组运行，匹配完整原计划和宿主决定后只核对已有成员；不准备、保存、批准或执行。缺失/损坏/错绑的事实或缺少宿主批准均不能报告成功，不用相同后镜像内容代替归因。

`BatchCallResult` 将公开 `ToolResultContent` 与私有调用计划、后端审批和实际组运行分开。公开输出仅保留有序路径、镜像摘要、成员状态/效果与组阶段/终止原因，不带原文、私有根路径、宿主批准人、调用审批摘要或成员 ID；上限48 KiB。部分效果为 failed，不是全组成功；任何未知为 unknown。全部已应用且后端 cancelled/timeout/interrupted 仍保留终止原因，宿主不得据 succeeded 结果清除 Turn 中断事实。

## 3. 异步生命周期

所有文件操作进入线程，并在桥接锁内串行；复用已有 ReadOperation、组执行器及 `_drain`，不重写文件替换/观察。每次操作的5秒预算在排队前创建，等待锁不刷新。此预算不是 Turn 生命周期：c3b 必须用持久创建时间计算原 Turn 剩余时间，将外层取消/超时传播到桥接；重开/审批/resume 不能刷新 Turn 时限。

Token 或 Task 取消置位线程停止信号，排空真实工作线程后才返回；取消后的后端内部预算仅用于已开始效果记账。关闭立即拒绝新任务并等待活动线程，重复关闭和关闭自身遭多次取消仍不得把写线程遗留后台。桥接不拥有副本，宿主先排空桥接再关闭副本。

## 4. c3b 持久化设计门禁（待实现）

独立整组审批 Item 绑定完整调用计划，旧只读/单文件审批不能升级为整组授权。顺序为 Session 调用 → 副本整组计划 → Session WAITING 审批 → Session 决定 → Session 持久离开 WAITING → 后端镜像组决定/一次执行 → Session 有界私有效果与公开结果。两个库非原子，各提交窗口均需恢复证据。

原等待状态可保留审批，已消费等待状态只允许 lookup/get_execution/reconcile，缺记录保持 unknown，不重试或自动继续模型。公开结果超限、取消和关闭也必须结算已发生的私有效果。按实际新增事件/结果定稿下一 Agent 与 Session 最低 reader 版本，使用真实 `6a7cc65` wheel 验证旧只读/单文件审批升级且原事件字节不变、旧 reader 拒绝；无后端存储需要不新增副本迁移。

## 5. c3c Artifact 设计门禁（待实现）

不得放宽只读发布器以接受任意写输出。新增基于真实已绑定整组调用/批准/效果的专用发布准入，并在 Session 同事务保存引用、正文和结果；计划展示不是授权，也不是实际效果。历史已归因 Diff 只包含 applied/observed_after 成员；unknown 单列，未执行后缀不得冒充变更。不能通过新造调用读取其他 Thread 的归档。

正文复用现有字节坐标 Diff，拆为有界 JSONL 记录，遵守单页24 KiB、整体1 MiB和配额/TTL；不把64 KiB报告当作单条记录绕过分页。展示截断标志与完整计划摘要分离。归档失败不能抹去已发生效果；恢复不重写目标文件或假造结果。

## 6. c3a 验收

真实多文件正常/拒绝/陈旧/部分/未知/审批重开；字段/调用/工具/副本/顺序/审批错绑，旧 Kernel 默认拒绝；Token、Task、排队截止与重复关闭；准备预留、镜像决定、组消费、每成员写前后、组结果及桥接返回的真实子进程退出。恢复禁止任何写入口，验证源目录与目标 inode/mtime/ctime 不变。基础 wheel、全量/异步回归和跨平台 CI；不将这些宿主测试计为尚未实现的 Session×组崩溃或真实模型验收。
