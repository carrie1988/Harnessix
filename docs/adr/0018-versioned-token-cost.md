# ADR 0018：版本化 Token 价格与可重算成本报告

- 日期：2026-09-03
- 状态：已接受，0.4.3a 已通过离线验收
- 前置：ADR 0016/0017；本切片不修改 Agent v4 / Provider v2 或 Session Migration

## 1. 问题与求证

Token 数量不是账单。相同 Adapter 可连接不同计费平台，模型别名、地域、服务等级、推理模式、输入长度和缓存 TTL 都可能影响费率。

- [OpenAI 官方价格文档](https://developers.openai.com/api/docs/pricing)：区分输入、缓存读取、缓存写入、输出，以及处理等级和上下文范围。
- [Anthropic 官方价格文档](https://platform.claude.com/docs/en/about-claude/pricing)：缓存写入 TTL 与地域可能影响计价，合作平台也有独立价格。
- [百炼官方价格文档](https://help.aliyun.com/zh/model-studio/model-pricing)：模型价格存在地域、输入长度阶梯和缓存差异。

这里只据此确定契约维度，不内置、抓取或猜测实时价格。测试费率全部为明确标注的虚构夹具，不以网页表格片段自动生成生产价格。

## 2. 本次交付与非目标

实现纯函数的尝试级 Token 成本估算，以及跨重试/Provider 的 Turn 成本报告。报告独立于会话事件，保存计算所需的完整价格、上下文、尝试快照和结果；JSON 重新载入时重新核算，不只相信已写入的金额。无网络、数据库写入或 Provider SDK 依赖。

这是**显式绑定价格后的事后估算**，不是已自动采集实际计费上下文、实时预算拦截、账单核对或支付服务。现有 Adapter 未采集的地域、实际服务等级和 TTL 不能自动补默认值；宿主必须提供已核对上下文，缺失则返回未知。固定费、服务器工具、多模态、税、促销、合同折扣、汇率和缓存存储费用不在范围内。

## 3. 价格契约

PriceSnapshot v1 使用不可变模型，包含：

- 版本标签、公开来源 HTTPS URL、生效区间 `[valid_from, valid_until)`；
- 计费平台、**实际模型**、地域、服务等级、推理模式、币种（首版 USD/CNY）；
- 适用的完整输入总量区间（两端包含）；一个快照代表一个阶梯，不是渐进分段计费；
- 输入计价二选一：全部输入同价，或未缓存/缓存读/缓存写分项；输出使用包含推理的总量，不再加推理子集；
- 分项价格可以明确要求缓存写 TTL；创建计数大于零时，未知或不匹配 TTL 不允许计算。TTL 要求为 null 表示该快照费率与 TTL 无关，不能用 null 代替未查清的规则。

单价必须为非负十进制**字符串**，最多 12 位整数和 12 位小数，统一每百万 Token。拒绝浮点数、布尔、指数、非有限值和未知字段。计算使用整数定点数，金额精确到由费率精度与百万单位导出的 18 位小数，不受 Decimal 全局上下文影响，也不在每次尝试按分四舍五入。展示层的货币舍入留待后续。

内容 SHA-256 识别具体快照；版本名称相同但内容变化不会被当作同一价格。哈希仅用于内容绑定与一致性检查，不是签名或计费来源真实性证明。

## 4. 尝试估算规则

PriceBinding 绑定参与计价的尝试快照哈希、内部 attempt_id、嵌入的 PriceSnapshot，以及由可信宿主提供的 BillingContext。快照只保留步骤/重试序号、实际模型、状态、用量和时间，不复制错误原文、请求模型或供应商响应 ID。价格不从 requested_model 或 Adapter 类型推导。

- ID/哈希错绑属于无效输入，直接拒绝；不能把旧快照绑定复用于更新了用量或状态的尝试。
- 尝试仍运行、用量非 complete、实际模型未知、上下文缺失/不匹配、生效期或输入区间不覆盖、必要输入分项/TTL 缺失时，金额为 null，并返回固定原因码。
- 失败/取消/中断但用量 complete 的尝试仍可估算；失败不等于免费。
- 整个尝试无法完整定价时不估算局部分项，避免输入阶梯或未知分项造成虚假的精确成本。
- 只有所有必要计数与费率明确时，才允许金额为 0；unknown 不映射为 0。
- 时间区间保守要求覆盖开始和结束，跨价格窗口不猜服务器采用哪个时点。

## 5. Turn 报告与兼容

报告按 attempt_id 一次计入最终尝试快照，不把多个累计观测或 ResponseCompleted 再加一次。未知尝试仍列出；旧 Provider 未暴露尝试的步骤列入 uncovered_steps。绑定重复 ID、额外 ID、重复尝试或越界步骤均拒绝。

只按币种分别汇总已成功估算的尝试，不把 USD/CNY 相加，不提供隐式汇率。报告完整性为 complete/partial/unknown；即使有已知小计，只要 Turn 尚未终结、存在未知尝试或未覆盖步骤，就不能展示成完整总成本。无尝试的报告保持 unknown。

报告不包含 Prompt、工具结果、HTTP Header 或原始 SDK 异常；不回填或改写历史会话。后续持久采集计费上下文需单独版本化设计，不能将当前事后报告冒充实时已绑定价格的账本。

## 6. 验收

- 严格单价与金额类型、极小/大额、整数定点精度、未知与已知零、上下文/TTL/阶梯/时间边界；
- 完成/失败/取消/运行中尝试，错绑/重复绑定、旧步骤、跨币种与重试去重；
- 报告 JSON 重载重算、金额或快照篡改检测、价格版本变化不修改旧报告；
- 两个实际 SDK + HTTP 替身 → Kernel/SQLite → 成本报告 → Replay 重算一致；
- 新 Schema 代码一致性、旧 Schema 冻结、全量回归与独立基础安装。
