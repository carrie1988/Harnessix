# ADR 0031：多文件计划、部分效果与有界结构化 Diff

- 日期：2026-09-04
- 基线：`3f42130`，CI `33840907282` 四项通过
- 状态：c1 已交付；c2a/c2b 已交付，分别见 ADR 0032/0033；c3a 宿主调用桥接已实现，c3b/c3c 待实现，见 ADR 0034

## 1. 源码核对与范围

现有 `PreparedPatch` 保存单文件完整镜像，`validate_prepared` 检查内部绑定，`verify_prepared` 只读观察来源；`ManagedPatchWorkspace` 已有单文件持久批准/意图/替换/观察。Kernel v6 写审批只绑定一个 ManagedPatchCallPlan，不能在不升级契约的情况下代表整组授权。Artifact 发布器绑定真实 Thread/Turn/Call，并与 Session 原子提交，不是任意路径 blob 存储。

因此复用单文件准备器、精确锚点与后端，不新增文件替换器；分三片交付：

| 切片 | 交付 | 本片是否执行 |
| --- | --- | --- |
| c1 | 严格多文件提案、不可变整组 manifest、只读准备/复核、有界结构化 Diff | 是 |
| c2 | c2a 整组预留/持久审批；c2b 逐文件消费、部分效果与只核对恢复 | 已交付 |
| c3 | c3a 宿主调用桥接已交付；c3b Kernel/模型、c3c Diff Artifact 待验收 | 部分 |

c1 不改变当前 apply_patch 输入、Agent v6、Session migration 7、副本账本 v1 或默认工具清单。它不是多文件执行器、Git Diff、审批凭证或自主 Coding Eval。旧单文件入口完整保留。成员仍是已有普通文件的精确编辑，不新增/删除路径或重命名文件。

## 2. 整组只读计划

新增独立 PatchBatchProposal：有序 files，每项复用 PatchProposal；同一路径不得重复，不自动排序或合并同文件提案。执行顺序将成为未来部分效果语义的一部分，故重排应改变整组指纹。

首版最多16文件，编辑文本 UTF-8 合计512 KiB；全部前后镜像合计最多8 MiB，单文件仍为既有1 MiB上限。限额是逻辑内容上限，不是进程 RSS 或数据库物理配额。全部提案先验证后才读取；实际镜像逐项累计检查，超过上限不返回部分可用整组计划。临时最多额外持有一个单文件计划。

PatchBatchManifest 包含 workspace_scope、整组提案摘要、有序的完整单文件 manifest 和自身指纹。PreparedPatchBatch 是宿主私有不可变载荷，不通过 repr 展示原始文本。内部复核必须覆盖提案顺序、每文件计划/镜像、总预算、共同工作区和整个 manifest，不只信任一个传入哈希。

准备完所有项后再次只读复核全部来源，捕获准备较晚文件时较早文件发生的变化。任一失败整组不返回；所有步骤共用 ReadOperation 的取消/截止时间。该过程仍不是文件系统同时刻快照，更不是与未来写入原子关联的 CAS。

## 3. 结构化 Diff，而非通用差异算法

只针对已验证的精确 Patch 编辑输出结构化变更，复用准备器的唯一锚点/重叠检查；不引入 difflib 对重复大文本的最坏平方级匹配。记录按文件提案顺序、文件内原文偏移排序，包括路径、单文件计划指纹、按原文偏移排序的编辑序号、前/后 UTF-8 **字节偏移**，以及旧/新片段的完整长度、SHA-256、有界文本前缀和截断标记。

偏移针对完整前/后镜像，后坐标累计此前编辑长度差；不是字符索引或行号，不把 CRLF、BOM、组合字符归一化。片段是精确编辑范围，不承诺最小行级 hunk、上下文或可交给 git apply 的统一补丁。

报告绑定整组计划指纹，始终保留 total_files/total_edits。输出从首项开始组成有界前缀；预算不足时停止，不跳到后续项伪装完整。truncated 同时反映未返回的编辑和片段正文截断。单片段最多4096 UTF-8字节，宿主默认1024；报告默认64 KiB、允许256字节至1 MiB，以实际 UTF-8 JSON 序列化长度验收。零正文预览仍保留长度/摘要；文本截断不切断 UTF-8 字符。

Diff 是观察/展示，不是授权或已提交证明。宿主必须使用完整计划批准，不能批准截断报告。c1 不把 Diff 自动送入模型或 Artifact；原始片段可能含用户代码和敏感内容，已有敏感路径规则不等于全文 DLP。

## 4. 后续持久多文件写的强制规则（待 c2/c3）

1. 整组请求/成员计划应在同一副本账本事务中预留，检查组预算与既有计划配额，避免只保存部分成员却发布整组批准。需要版本化账本与旧 reader 拒绝，不原地改变 v1 含义。
2. 整组审批绑定调用、工作区/副本、有序完整成员计划和整组摘要；旧单文件 ApprovalRecord 不升级为任意组授权。审批答复与执行仍分离。
3. 执行前先整组复核，成员写前仍重新复核；已知陈旧组不启动写入，但这些检查仍不构成跨文件事务。每文件的持久意图先于真实效果；严格顺序执行，遇到首个失败/不确定或取消即停止调度后续成员。已成功成员保留，不自动回滚，也不将未开始者写成失败执行。
4. 组效果至少区分全未应用、全已应用、已知部分应用及含未知成员；Turn 终止原因与文件效果分开。部分应用不是原子失败，全成功也不能抹去宿主中断事实。
5. 恢复逐成员核对已有计划，不新建/再批准/再执行。未开始者保持未开始，observed_before 不意味着可沿用旧批准继续；未知优先于“已知全部失败”。
6. Diff 表示计划变化还是历史实际效果必须明确区分；后者只包含已归因的写入，未知成员单列，不把计划 Diff 冒充实际工作区 Diff。
7. Kernel 必须新增整组审批/结果兼容契约，再开放独立版本化工具；Session 与副本仍非同事务。Diff Artifact 复用实际调用归属和 Session 发布器，不能伪造 ToolResult 或跨 Thread 读取。

精确持久字段与副本账本 v2 已按实际 API 固化在 [ADR 0032](0032-durable-batch-reservation-and-approval.md)。审批记录不冒充执行状态机；实际组消费/效果记录由 [ADR 0033](0033-batch-consumption-and-effect-recovery.md) 独立版本化，未提前修改审批 Schema。

## 5. 验收门禁

c1：严格字段/路径/重复/顺序/预算，真实多文件准备且无磁盘写，准备期间来源漂移，整体载荷错绑，超时/取消，UTF-8/BOM/CRLF/无末尾换行，前后字节坐标可重建目标，长片段/JSON转义/极小预算不超限，截断不谎报完整，旧 Schema 字节不变、旧 Patch 全量、基础 wheel 及 Linux/macOS CI。

c2/c3 另须覆盖所有成员位置的失败、拒绝、取消、fsync/记录异常，组事务前/后、每成员替换前/后及组结果发布前/后的真实退出；恢复不重复写、源目录不变、旧会话/账本升级、两个 SDK 离线闭环和 Artifact 归属/配额/过期。c1 的只读计划测试不能计为这些写恢复证据。
